# 信息图骨架推导法

规律来源：`sample_prompt/` 下的六份优秀样本（城市系统图谱、相机成像图谱、医学因果链、地铁工程参考页、博物馆图鉴、导览绘本）。

## 一句话规律

优秀的信息图提示词不靠形容词堆高级感，而是**先把信息结构写成清单**——谁在什么位置、分几块、每块叫什么、有几项——再交给模型画。画质靠"单一超写实主视觉 + 分区信息板"，稳定性靠"数量约束 + 短标签 + 负面清单"。

## 第一步：判定主体类别

| 主体类别 | 识别信号 | 主线推导 |
| --- | --- | --- |
| 系统 / 流程 | 涉及装置、设备、工艺、链路、生产、运维 | 抽出 4–8 个有序环节，构成从输入到输出的链路 |
| 器物 / 人物 | 单个物件、服饰、器械、角色、造型 | 外形 → 关键部件 → 材料工艺 → 局部特写 |
| 概念 / 机制 | 原理、效应、因果、调控、对比 | 输入 → 转化 → 输出，再补一组对比 |

系统 / 流程类是最常见的一类，也是本技能的主力场景。

## 第二步：把主线变成骨架

主线环节要**同时**驱动三处，三者必须一一对应：

1. `centerpiece` 的剖切层级或部件排布；
2. 编号面板的顺序（每个环节至少一个面板）；
3. `layout.bottom_row` 底部流程条的分步标签。

### 推导示例：相干衍射成像 CDI

环节：相干光源 → 针孔与光束整形 → 样品与过采样衍射 → 远场探测器采集 → 相位恢复迭代 → 重建图像与分辨率评估。

映射结果：

- 主视觉：三维剖切的 CDI 实验腔，光路自左向右贯穿，发光青色束线连接各环节；
- 面板：01 相干光源 / 02 光束整形 / 03 样品与过采样 / 04 远场采集 / 05 相位恢复 / 06 重建评估；
- 底部流程条：相干照明 → 过采样衍射 → 强度采集 → 相位恢复 → 重建成像。

完整成品见 `references/examples/cdi-infographic.json`。

## 第三步：套固定版式

| 位置 | 内容 |
| --- | --- |
| 顶部 | 中文主标题 + 一句话副标题 |
| 左上 | 总览小图、定位图或原理示意 |
| 右上 | 数据表（写死行数） |
| 中段 | 左右分栏，每侧 2–4 个编号面板，围绕主视觉 |
| 底部 | `bottom_row` 收束：流程条 / 因果链 / 核心总结 |

## 第四步：按公式写面板

每个面板都写成 **编号 + 中文标题 + 元素类型 + 数量**：

> `04` `远场衍射采集` —— `1 张衍射图样示意 + 1 张探测器读出链示意 + 4 条图例`（`count: 4`）

配套的中文图例标签放进 `labels`，每条只写几个字。宁可多几个面板，也不要把一个面板写成一段话。

## 第五步：写风格与负面清单

`style` 要包含四件事：背景、主色与点缀色、材质与光线、排版气质。可用的风格锚点：

> 工程参考书页、博物馆展板、技术图鉴、系统剖面图谱、科研手册跨页、信息密集型知识页

深色科技风与浅色临床风都成立，选一种并贯彻全套配色。

`avoid` 从下面的词库里挑 ≥5 条：

> 海报广告感、影楼感、电商详情页感、动漫或卡通风、赛博霓虹过载、杂乱拼贴、糊字或乱码、错字与拼音、结构错误的器件、假材质、过度装饰、大段文字段落

## 自检

- 主线环节是否写具体了？"若干光学元件"不合格。
- 每个面板是否都有编号、中文标题、元素与数量？
- 是否有 `bottom_row` 收束？
- 主视觉是否是写实的剖切 / 爆炸视图？
- 所有图中文字是否都是中文（专有名词可保留原文）？
- `avoid` 是否 ≥5 条，且针对模型的常见退化模式？
