# Img Prompt：生图 JSON 提示词撰写

## 定位

输入一句主题，输出一份结构化 JSON 提示词。用户把这份 JSON 直接粘贴到任意生图工具（Nano Banana / Gemini、Seedream、Qwen-Image、即梦、Midjourney 等）即可出图。

本技能不调用任何生图 API：没有密钥、不下载网络资源。最终交付物是**项目空间里的一个 JSON 文件**——写到当前工作目录的 `prompts/` 下，对话窗口只汇报路径与要点。

如果项目已有约定的提示词目录（例如 `assets/prompts/`、`docs/prompts/`），以项目约定为准，并在交付说明里写清实际路径。

如果用户直接说"给我生成一张图"，仍然只产出 JSON，并补一句：这份 JSON 可直接粘贴到常用的生图工具。

## 工作流

1. **判类型**：按下面的路由表确定 `genre`。
2. **判子类型与画幅**：信息图先分"科普图（知识解说型）"还是"信息图（结构数据型）"，从 `references/infographic-atlas.md` 的子类型表里挑一个写进 `subtype`，并按用途表把画幅写进 `canvas`；海报按 `references/poster.md` 选子类型，画幅默认 `4:5`。
3. **推导骨架**：按 `infographic-atlas.md` 或 `poster.md` 的推导法列出主线环节（信息图）或文字层（海报）。主题越具体，主线就要越具体——写"相干光源、针孔、样品、探测器、相位恢复"，不要写"若干光学元件"。
4. **填 JSON**：严格按 `references/prompt-json-spec.md` 的字段与必填规则写。需要参照密度与语气时，读 `references/examples/` 里的完整示例。
5. **自检并落盘**：把 JSON 通过标准输入交给校验脚本，按提示修掉问题；校验通过的同时写入项目 `prompts/` 目录：

   ```powershell
   $json | python "<技能目录>\scripts\validate_prompt_json.py" --stdin --out prompts
   ```

   脚本会打印落盘路径（如 `prompts/infographic-相干衍射成像-CDI.json`）。校验有错时不会写文件，先改完再跑一次。

6. **汇报**：对话里给一句话交付说明——类型与子类型、骨架主线、保存路径，并说明文件内容可直接粘贴到生图工具或再迭代。用户明确要"贴出来看看"时，再把 JSON 代码块贴进对话。默认只保存一份；用户要多个方案时再存 2–3 份，共用同一骨架、替换风格与配色。

## 输出文件

- **位置**：当前项目工作目录下的 `prompts/`（没有该目录时脚本自动创建）。
- **命名**：`{genre}-{主题}.json`，例如 `infographic-相干衍射成像-CDI.json`、`poster-城市黄昏.json`。同名已存在时脚本追加 `-2`、`-3`。
- **格式**：UTF-8、2 空格缩进、中文不转义，直接可读可粘贴。
- **只落盘校验通过的稿子**：不要手写文件绕过 `validate_prompt_json.py`；先校验、后保存，避免项目里留下带占位符的半成品。
- **改稿**：用户要求修改时，直接改原文件（沿用原文件名），不要另存一份游离的新文件。

## 类型路由

| 用户信号 | 类型 | `genre` |
| --- | --- | --- |
| 海报、poster、宣传、展览、旅行、电影感、拼贴、字体海报、收藏海报 | 海报 | `poster` |
| 信息图、图谱、拆解、剖面、图鉴、原理、流程、系统、结构、"介绍一下××并配图" | 信息图 | `infographic` |
| 两类信号都有，或只给了主题 | 默认信息图；交付时补一句"想要海报版我可以再出一份" | `infographic` |

判定为信息图后，再到 `references/infographic-atlas.md` 的子类型表里定 `subtype`（科普图鉴 / 结构拆解 / 系统手册页 / 因果链 / 流程步骤 / 数据宫格 / 地图导览 / 分析报告 / 人物档案），并按用途表定 `canvas.aspect`。

## 不可退让的硬约束

- **全部中文**：图中出现的文字（标题、副标题、面板标题、图例标签、海报文案）一律中文。专有名词可保留原文（CDI、FDTD、某型号），但同一条文字里必须含中文。
- **先定画幅**：信息图也必须写 `canvas.aspect`（按用途选 `9:16` / `3:4` / `A4` / `1:1` / `16:9`），海报写 `4:5` 或指定比例。画幅不写，模块必然挤成一团或空成一片——这是信息图最常见的翻车点。
- **写清子类型**：信息图的 `subtype` 从子类型表里挑一个（科普图鉴 / 结构拆解 / 系统手册页 / 因果链 / 流程步骤 / 数据宫格 / 地图导览 / 分析报告 / 人物档案），并按它决定主线。
- **一句定性**：`type` 要点明"这是什么图、不是海报"，例 `博物馆图鉴式中文拆解信息图`。
- **数量写死**：每个面板都要写清元素类型与数量，例如"1 张剖面示意 + 4 条图例"。
- **文字与数字写死**：要出现的标题、标签逐字给出，并写明"简体中文、清晰规整、不乱码、不错字、不拼音"；参数连单位写死（`λ = 632.8 nm`、`1280–1350 ℃`）。不确定的内容不要编造，写"相关记载较少"。
- **文字防退化**：`avoid` 里必须含"海报广告感"与"乱码 / 错字"两类条款。
- **选一套视觉系统**：纸感文博系 / 现代白底系 / 暗色科技系三选一，并在 `style` 里落到具体材质词（手工和纸、亚麻纹理、哑光厚艺术纸、拉丝钛金属、冷凝水……）。
- **底部收束**：信息图必须有 `layout.bottom_row`，作为流程条、因果链或核心总结。
- **负面清单**：信息图 `avoid` ≥ 5 条，海报 `avoid` ≥ 3 条。
- **写实主视觉**：信息图 `centerpiece` 是 1 个超写实三维剖切或爆炸视图，不是拼贴、不是卡通。
- **步骤类写动线**：做法、流程、教程类必须给动线（Z 字形、蛇形、顺时针），否则模型会把步骤排成一列小格子。
- **不留占位符**：不要出现 `[TITLE]`、`{argument ...}`、`TODO`、`xxx` 之类内容，该填的直接填。
